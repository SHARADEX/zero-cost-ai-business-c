Understanding JWT Tokens: A Beginner's Guide

Published: 2026-01-25 · Tags: webdev, security, tutorial

JSON Web Tokens (JWT) are everywhere in modern web authentication. If you've built a web app in the last 5 years, you've probably used them. But what exactly is a JWT, and how do you inspect one?

What is a JWT?

A JWT is a compact, URL-safe way to represent claims (information) between two parties. It's encoded as a string with three parts separated by dots:

header.payload.signature

The Three Parts

1. Header

The header typically consists of two parts: the token type (JWT) and the signing algorithm (e.g., HMAC SHA256).

{
  "alg": "HS256",
  "typ": "JWT"
}

2. Payload

The payload contains the claims — statements about an entity (typically the user) and additional data.

{
  "sub": "1234567890",
  "name": "John Doe",
  "iat": 1516239022
}

3. Signature

The signature is used to verify the token wasn't tampered with. It's created by signing the encoded header + payload with a secret key.

Inspecting a JWT

JWTs are base64url-encoded, so they're easy to decode. You can use our JWT Decoder — just paste the token and see the decoded header and payload.

Important: Decoding a JWT doesn't verify it. Anyone can decode a JWT — the security comes from the signature, which only the server can verify.

Common Claims

  • iss — issuer
  • sub — subject (usually user ID)
  • aud — audience
  • exp — expiration time
  • iat — issued at

Security Best Practices

  1. Always verify the signature on the server.
  2. Use HTTPS — JWTs in transit should always be encrypted.
  3. Set short expirations — refresh tokens should be used for long sessions.
  4. Don't store sensitive data in the payload — it's encoded, not encrypted.

Conclusion

JWTs are powerful but come with responsibilities. Use our JWT decoder to inspect tokens during development, and always verify signatures server-side.
